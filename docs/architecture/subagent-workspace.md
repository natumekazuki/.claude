# Subagent Review Boundary

委譲前に読む。ClaudeのAgentへ、対象、必要な結果、権限を依頼ごとに渡す。調査だけの依頼では編集しない。履歴継承に頼らず、review依頼には主要動作、後続の依存、[開発・review・統合](../guides/development.md)の統合基準と、非ブロッカーを全件修正待ちにしないことを含める。必要な参照先は参照元文書から解決した実pathで渡し、全規約を無条件に複製しない。

共有する設計判断に関わる依頼では、必要な要求・前提、採用済みの判断と適用状況、未合意事項、[設計判断・文書化](../guides/design-decisions.md)の参照先も渡す。同じ前提の判断を再利用し、現行実装や草案を採用根拠に置き換えない。不足の調査・推奨案・草案作成までを依頼できるが、親からの委譲を未合意方針の採用や操作権限の拡大と解釈しない。

## runtimeと権限

モデル・effortはユーザー指定と利用中のClaude設定を維持する。他製品のモデル名、role名、tool引数を流用せず、Claude側で合意された担当分けがある場合はその範囲で選ぶ。役割名だけで実モデルを推測しない。必須の委譲を実施できない場合は未実施を報告し、親の自己評価で審査済みにしない。形式的な試行、念のための多重reviewは追加しない。

Agent起動は現在のtool schemaに従う。対象・必要な文脈・完了条件を起動時の依頼へ含め、親の会話や既読fileが子へ渡ることを前提にしない。必要な資料だけを渡す通常の独立した委譲を使い、履歴全体のforkを暗黙に要求しない。

read-onlyの依頼は文面だけでなく、利用するagentのtool制限と実効権限を確認する。permissionModeだけを読み取り専用の保証にしない。shell、編集・write、外部writeを行えるMCP等を一律に引き継いだまま、制限済みと報告しない。必要なread-only構成が利用できない場合は、その委譲に依存する完了判断を止め、権限を無断で追加・迂回しない。

本repositoryの汎用read-only担当は[`agents/read-only.md`](../../agents/read-only.md)である。`model: inherit`を使い、toolはRead・Glob・Grepだけに限定する。review観点は依頼ごとに渡し、test専用roleにはしない。runtimeでこの担当と有効なtool構成を確認し、同名のproject・managed定義が優先される場合はその実体を確認する。

待機・再開・結果取得はClaudeの現在のAgent契約に従い、通知と完了見込みを使う。短い間隔のポーリングや、他製品の待機toolの引数を持ち込まない。

## 統合と成果返却

test価値reviewの抽出、read-onlyサブエージェントへの委譲、review観点、完了判断は、runtimeが提供するreview-test-value Skillを正本とする。専用roleや独自のworker、scheduler、artifact storeは使わない。必須Skillやread-only担当が利用できない場合は審査を免除せず、実施できない条件を報告する。

同じworking treeで作業する場合は編集範囲と生成物の競合を避け、ユーザーと他の担当の変更を保護する。子は結果、根拠、実行した確認、未解決事項を親へ返し、親が統合と最終確認を行う。通常の成果返却に専用文書は不要である。

worktreeやcommit固定は具体的な隔離・再現の必要に応じて使う。全reviewへ一律に別worktreeを要求しない。

非ブロッカーは上記の統合基準に従って別の修正タスクとして扱い、その着手・完了を現在の変更の完了・統合条件にしない。
