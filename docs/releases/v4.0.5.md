# v4.0.5

WithMateの子Sessionの作業領域分離と、親による準備・回収・復旧の責務を定める互換修正版です。

## 変更内容

- [委譲と作業領域](https://github.com/natumekazuki/.claude/blob/aab3932a3909395bca91016412d267746e45ca48/docs/architecture/subagent-workspace.md)で、通常のMain Sessionを全体統括・個別統括・Workerを問わず1 Session・1専有Workspaceとし、同じ作業directoryを複数のSessionへ重複割当しないことを定めました。子を起動する直接の親が専用作業領域を作成・確認して絶対pathを渡し、準備に失敗したら子の起動を保留します。Git管理下の通常子にはreviewを含めて専用Worktreeを割り当て、既存Worktreeは他Sessionの占有を確認してから使い、forceで同じbranchを複数checkoutしません。作業領域の再利用・回収の条件と、Git管理外の作業での専用directoryの運用も定義しました。
- [Session間の協同](https://github.com/natumekazuki/.claude/blob/ef9bbca1289a242ed9a3ed78a35288f8a2331d81/docs/guides/withmate-collaboration.md)で、子の作成前の専用領域の準備と、全体統括・個別統括が直接行える範囲に作業領域の準備・回収を含めることを明確にしました。「全体統括は実際のGit操作を担当へ委譲する」旧規定は、作業領域の管理を統括の直接操作へ含める定義へ置換しています。
- [委譲と作業領域](https://github.com/natumekazuki/.claude/blob/c3675bd19c7eba3933e2cb7da6b0d8776c6e3f24/docs/architecture/subagent-workspace.md)で、割当Workspaceの不在を理由に子Sessionへの送信が拒否された場合の復旧を送信元Sessionが担うことを定めました。未配送（`effect: none`）が確認できた場合に限って再送し、受付結果が不明なら同じrequestIdと宛先で確認して重複送信を避けます。
- [共通入口](https://github.com/natumekazuki/.claude/blob/32f5a6d5213c97392f8521af6326685d6ac0747f/CLAUDE.md)と[Session間の協同](https://github.com/natumekazuki/.claude/blob/ef9bbca1289a242ed9a3ed78a35288f8a2331d81/docs/guides/withmate-collaboration.md)で、委譲の依頼本文を依頼する側が自身の言葉で伝えることを明確にしました。ユーザー発言の転載や言い換えだけで依頼を済ませず、原文を扱う作業では依頼と資料を分けて、コード・ログ・指定文言など正確さが必要な資料を改変しません。共通手順の全文再掲はせず、辿れる入口を示します。

## 互換性・更新時の注意

Skill名・配置入口、抽出CLI・result・metadata schema・adapter・Git差分選択、操作承認の契約は変更しません。本版の変更はWithMateの作業領域運用と委譲文面の規約のみです。Auxiliaryとnativeサブエージェントは専有Workspaceルールの対象外であり、既存の編集所有・衝突回避・権限は維持します。既存homeへは対象文書の差分を反映し、実設定・認証・履歴等を上書きしないでください。

## 確認範囲

v4.0.4以降の変更差分、参照先のheading・anchor、`git diff --check`を確認しました。Workspace専有・親の準備回収・送信元復旧・委譲文面の条文は、共通規定の基準として確定したCodex repositoryのcommit `4affded` と一文単位で照合し、必要な差分を反映しています。

生成応答の比較、各Providerの新規Sessionでの実適用、live配置は確認対象に含みません。
